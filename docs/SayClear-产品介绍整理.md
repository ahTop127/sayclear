## 1. 一句话定义

用户用自然语言（说话）随意表达需求；**SayClear** 负责清洗、纠错、分点、格式化，锁定真正想说的内容后，把正文填进当前输入框。

SayClear 是一层智能输入：把混乱表达整理成可执行输入，而不是只做语音转文字。

---

## 2. 目标用户（已明确）

高频使用 AI 工具和搜索引擎的人，尤其是学生、产品经理、开发者及其他知识工作者。

---

## 3. 问题与价值（已明确）

说话时常见口头禅、重复、停顿、自我纠正、顺序混乱。直接转写后内容冗余、前后矛盾、多需求混杂，用户不知道有没有被理解，只能反复改输入。

| | 普通语音输入 | SayClear |
|---|---|---|
| 做的事 | 把「我说了什么」变成文字 | 理解「我到底想表达什么」，变成可直接使用的输入 |
| 结果 | 原始转写 | 清晰、结构化的正文（有分点就分点，没有就写通顺） |

主流程：自然表达 → 智能整理 → 结构化输入 → 用户正在用的输入框（AI / 搜索 / 其它，同一套逻辑）。

---

## 4. 功能需求（第一期五个全部上）

五个能力是同一条处理链，第一期全部交付。默认全部生效；是否可单独开关见功能需求文档「待确认」。

### 4.1 语义清洗

去掉口头禅、重复、卡顿等无效表达，保留真正想说的信息。

### 4.2 智能纠错（自我修正）

识别自我修改，以前后最终意图为准，丢弃被否定的旧说法；补充则保留。

### 4.3 智能分点

多个并列需求或步骤整理成 1、2、3；只有一件事或连贯叙述则不分点。

### 4.4 智能格式化

按内容选择段落或分点。**不**按「给 AI」或「给搜索」做两套模板。

### 4.5 意图确认

抽出并锁定核心需求。第一期**默认不弹确认层**，直接把锁定后的正文填入输入框，**不代发**，也**不弹成功提示**；若要改字，直接在目标输入框里改。第一期不做「打开修改」。填入的不是「我理解你的需求是……」。

---

## 5. 使用场景

同一套整理逻辑，任意输入框：

1. 对着 AI 对话框说话，得到可发送的正文。  
2. 对着搜索框说话，得到同样规则整理后的正文（不是另一种查询模板）。  
3. 多条修改点 → 结构化分点。  
4. 边想边说、中途改口 → 只保留最后意图。

---

## 6. 产品形态（已确认）

第一期是 **Mac 桌面悬浮工具**：

- 全局快捷键 **Command（⌘）** 开始 / 结束录音（单击切换：按一次开始，再按一次结束；**仅录音**，不支持打字 / 粘贴再整理；使用 Command，不用 Ctrl）
- 口述交给**外部识别 / 整理服务**完成「语音 → 文字」和「文字 → 结构化结果」；用户接受把口述发给这些服务（不是本机 / 外传选择题）
- 说话时出现暗黑圆角录音条：左 X 取消、中间波形、右 OK 结束
- 识别 / 整理中只显示 **Thinking**
- 整理完成后直接填入当前任意输入框，无确认层、无成功提示
- 不代发
- 若要改字，在目标输入框直接改（不做「打开修改」）
- 中英混合可用
- 不是浏览器插件、输入法、独立网页

---

## 7. 范围

### 第一期纳入

- 全局快捷键录音（⌘，单击切换）
- 五步整理（清洗 / 纠错 / 分点 / 格式化 / 意图确认）全部上线
- 直接填入；要改就在输入框里改

### 第一期不纳入

- 账号、付费、历史同步、团队协作
- 自己做搜索或自己做对话产品
- 插件、输入法、网页版、手机端、Windows
- 打字 / 粘贴乱口语再整理
- 自动发送
- 「打开修改」悬浮层与第二套修改快捷键
- 填入成功提示条
- 按当前 App 切换 Prompt / 搜索两套模板
- 把「能否不把口述交给外部服务」做成开关

---

## 8. 已定与待确认

已定项以功能需求文档第 2 节为准。草稿里原先待确认、现已拍板的：

- 打字 / 粘贴：第一期**不支持**
- Prompt 与搜索：不区分，同一类内容、同一套输出规则
- 五个功能：第一期**全部上**
- 口述处理：走外部识别 / 整理服务；**不是**「内容能否离开本机」的待选项
- 快捷键：Command（⌘）单击切换；不用 Ctrl
- 填入后改字：在目标输入框直接改；不做「打开修改」
- 整理中文案：只显示 Thinking；填入后无成功提示条

仍待确认的（焦点变化填入哪一个框、⌘ 是否与系统冲突、Thinking 时再按 ⌘ 等）只列在功能需求文档第 11 节，本文不再展开。
